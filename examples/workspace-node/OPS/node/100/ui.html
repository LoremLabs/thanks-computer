The node's admin UI listens on the node's own loopback, and the workspace has no inbound route. What you see here is a browser running on the node's workspace, beside the chassis, shown through the parent. open the node's UI checks the node is up (/setup), starts that browser (/ui/setup, about two minutes the first time), signs it in to the node's admin UI with the node's own key (/ui/open), then binds the workspace's display to a WebSocket (/screen) that noVNC renders. The page polls /ui/setup every 15 s so the workspace is not frozen under you.
